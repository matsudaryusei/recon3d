## 読むもの1：[計画書 §3-8 スコープの明示](../plan.md#s3-8)

**5行の表です。** 特に見るのはこの2つ：

| | 中身 |
|---|---|
| **やらないこと** | **リアルタイム描画・ゲームエンジン連携は扱わない。** 静止画20枚を一括処理して立体を作り、精度を数値で測るのが本体 |
| **自作の範囲** | **反復解法・最適化・幾何アルゴリズムは自作する**（ここがプロジェクトの芯）。**行列積・I/O・画像前処理はライブラリに任せる** |

> **「リアルタイムに動くものを作りたい」と思っていた場合、ここで言ってください。** L4（余力があれば）に「ボクセルが削られる過程のビューア」を置いてあるので、**受け皿はあります。**

---

## 読むもの2：[計画書 §12 撤退ライン](../plan.md#s12)

**4段階と、2回の判定日です。**

| 段階 | 到達内容 |
|---|---|
| **L4** | 統合 ＋ 実験 ＋ ビューア/GUI ＋ ドキュメント一式（理想） |
| **L3** | 統合パイプライン完成、Blender 出力、比較実験 E1–E7（**これが目標**） |
| **L2** | ④のみ（既知のカメラ姿勢で Visual Hull）でメッシュ生成（合格ライン） |
| **L1** | ①のみ、自作バンドル調整で点群生成＋収束実験（最低保証） |

**判定日**：

- **★2026-11-01（W11 終了時）**：バンドル調整が収束しているか？ **収束しなければ L2 に落とす**
- **★2026-11-29（W15 終了時）**：メッシュが出ているか？ **破綻していれば L1 に落とす**

> **なぜ先に決めてあるのか**：「もう少し頑張れば」で判断を先延ばしにすると、**最後に何も残らない**からです。
> **L1 でも L2 でも、それ単体で成果物になるように組んであります。** 落とすことは失敗ではありません。

| 症状 | 対処 |

| **読んでも言葉が分からない** | [用語集](../glossary.md) を並べて開く。**`点群`・`メッシュ`・`バンドル調整`・`Visual Hull` の4つだけ**分かれば読めます |

| **納得できない点があるが、言い出しにくい** | **言ってください。それがこのタスクの目的です。** [計画書 §14](../plan.md#s14) の 13 に「保留のまま流れやすいので、最後に必ず聞く」と明記してあります |
