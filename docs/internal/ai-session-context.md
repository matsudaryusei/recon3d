### ⚠️ 手順書（`../tasks/`）で越えてはいけない線【2026-08-24 追加・最重要】

**`tasks/` の手順書には、意図的に書かれていない部分がある。** 空欄・未記入に見えても**穴ではない。埋めてはならない。**

| 手順書に書いてある（＝補完してよい） | **意図的に空けてある（＝絶対に埋めない）** |
|---|---|
| 環境構築・ツール操作（`uv`・Git・GitHub 画面） | **アルゴリズムの導出・数式の変形** |
| 設定ファイルの中身（`ci.yml`・ラベル定義） | **実装コード**（関数シグネチャと通すべきテストまでが上限） |
| 打つコマンドと期待出力 | **テストの期待値**（本人に導かせる） |
| 完了したと分かる観測方法 | **比較の結論・設計の選択**（どちらが良いか） |
| 既知の罠への対処 | **調べれば分かることの要約** |

**判断基準**: **「そこで詰まって時間を使うことに、学びがあるか」**。
`uv sync` が通らず2時間溶かす → 学びなし → **全部書く**。座標変換の符号を自分で導いて間違える → **その間違いが理解になる** → **書かない**。

**具体例**: `../tasks/T01-pairpro1-io.md` は `io/coords.py`・`io/cameras.py` の**シグネチャと docstring だけ**を置き、本体を空けてある。
**「親切のつもりで実装を書き足す」ことは、[D-33](../decisions.md#d-33)（生成AIを使わずに書きたい）と [計画書 §3-8](../plan.md#s3-8)（数理は自作するのが本プロジェクトの芯）の両方に反する。**
**知識が足りないと判断した場合の正しい対応は、実装を書くことではなく `../learning.md` に資料を1本足すこと。**

この線引きは `../tasks/README.md` にも人間向けに明記してある。

## 文書運用のルール

このプロジェクトの文書は役割で分かれている。**書き足すときは置き場所を間違えないこと。**

| 内容 | 置き場所 |
|---|---|
| 決まったこと（仕様・手順・日程） | 計画書 |
| **なぜそう決めたか**（根拠・代替案・却下理由） | **決定記録**。計画書には書かない（肥大するため） |
| **完了したタスクと完了日** | **`../next.md` の状態列**（`✅ 完了（日付・PR番号）`） |
| 詰まった点・書きながら学んだこと | `../memo/` ・ `../notes/` |
| **実績を見て計画を直したこと** | **`../decisions.md` の[計画を変えた記録](../decisions.md#changes)** |
| **次に何をするか**（残タスクと状態） | **`../next.md`**。README には書かない |
| **どうやるか**（手順・完了判定） | **`../tasks/T<番号>-*.md`**。**仕様は書かず計画書へリンクする**（二重管理を避ける） |
| 用語の定義（1行） | `../glossary.md` |
| 学習資料へのリンク | `../learning.md`（**ジャンルごと3本まで。要約は書かない**） |
| 詰まった記録・調べたメモ | `../notes/` |
| 松田への確認事項 | **文書を作らない。** 口頭で聞き、決まったことを Issue / PR に1〜2行残す（計画書 §8-3） |
| 人間が最初に見るもの | README |

**決定を変えたときは、決定記録の項目を消さずに改訂履歴として追記する**（「かつてこう決めていて、こういう理由で変えた」が残っていること自体が共同開発の説明材料になるため）。

## 注意：文書が長くなりすぎた経緯

2026-08-15 時点で docs 配下が4000行を超え、**関口から「どれを読めばいいか分からない」という指摘があった。** そのため：

1. `README.md` を人間向けの唯一の入口として新設
2. 手続き用・履歴用の文書を `internal/` に分離（本ファイルを含む）
3. 計画書から「セッション引き継ぎ用」の記述を本ファイルへ移動

**今後、文書を追加・拡張するときは「人間が読む必要があるか」を先に判断し、無ければ `internal/` に置くこと。** README は短く保つ。

**2026-08-16 追記：松田からも同種の指摘があった。**

> 「質問多すぎ。ファイル数少ないのに似たファイル名で名前長い」（コミットメッセージ）

**対応済み**：① **確認シートは第2版で打ち止め。回答を反映したうえで第2版のファイルごと削除した（2026-08-17）。** 以降の確認は口頭で行い、決まったことだけを Issue / PR に1〜2行残す運用に切り替えた（計画書 §8-3）。② **`doc/` → `docs/` 改名と、ファイル名からの `3d-reconstruction-` 接頭辞の除去を実施（2026-08-17）**（計画書 §16）。

**AIへの指示**: **このプロジェクトで新しい質問票・大型の文書を提案しないこと。** 2人とも文書量に対して既に不満を表明している。**追記は既存ファイルの該当節に行う。**
