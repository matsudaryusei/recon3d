# notes/ — 詰まったことと、分かったことの置き場

**ここは「調べた結果」と「詰まった記録」を置く場所です。**

[Discuss.md の 8/17](../../Discuss.md) で、こう依頼が出ています:

> ログファイルを清書するときは詰まった点や工夫した点など**振り返りを書くように事細かく冗長に**書こうと思っています。
> 思い返せるように、**個人が作成した範囲でメモを残しておいてください**

**その置き場がここです。** [進捗ログ](../progress.md) は週1回の要約なので、詰まった中身までは入りません。**細かい話はこちらに1本ずつ**書いて、進捗ログからはリンクするだけにします。

---

## 何を書くか

| 書くもの | 例 |
|---|---|
| **詰まって、解決したこと** | 「`import` が通らなかった。原因は◯◯だった」 |
| **調べて分かったこと** | 「Blender の CLI レンダリングはこう書く」 |
| **比べて選んだこと** | 「マスクの方式を4つ比べた」（→ [T07](../tasks/T07-mask-options.md)） |
| **相手のジャンルへの説明** | 自分が作った部分を、専門外の相手に向けて説明する1枚（[計画書 §3-7](../plan.md#s3-7)） |

**書かなくていいもの**：週次の実働時間（→ [進捗ログ](../progress.md)）、決定の理由（→ [決定記録](../decisions.md)）、仕様（→ [計画書](../plan.md)）。

## ファイル名

`<日付>-<内容>.md` か `<内容>.md`。**どちらでもよいですが、後から探せる名前**にしてください。

```
docs/notes/blender-entry.md              # 恒久的に引くもの
docs/notes/mask-options.md               # 比較・検討したもの
docs/notes/2026-08-20-icloud-venv.md     # 一度きりの障害記録
```

## テンプレート（詰まった記録）

**コピーして使ってください。埋まらない欄は空のままで構いません。**

```markdown
# <何が起きたか>（YYYY-MM-DD・<環境>）

## 症状

（何をしたら、何が起きたか。**エラーメッセージはそのまま貼る**）

## 試したこと

| # | やったこと | 結果 |
|---|---|---|
| 1 | | |
| 2 | | |

## 原因

（分かったなら書く。**分からないまま解決したなら「不明」と書く**。それも情報です）

## 解決した方法

（同じことが起きた人が、これを読んで再現できる形で）

## 分かったこと・次に活かすこと

（1〜3行。**ここが一番あとで効きます**）
```

## テンプレート（調べたことのメモ）

```markdown
# <調べた対象>

**調べた日**: YYYY-MM-DD ／ **調べた人**: <名前>
**きっかけ**: （どのタスクのために調べたか。手順書へのリンク）

## 分かったこと

（箇条書きでよい）

## 使い方・最小の例

（動くものを1つ。**自分で動かして確認したものだけ**を載せる）

## まだ分かっていないこと

（**空にしない。** 分かっていない範囲を書いておくと、次の人が同じところで止まらない）

## 参考にしたもの

- （URL）
```

## 書くときのコツ

- **冗長でかまいません。** [Discuss.md](../../Discuss.md) の依頼どおりです。**削るのは後からできます**
- **「当たり前すぎて書くまでもない」と思ったことこそ書いてください。** 3か月後の自分には当たり前ではありません
- **解決していなくても書いてよい**です。「ここで止まっている」は立派な記録で、相手が拾えます
- 用語で迷ったら [用語集](../glossary.md)、資料が要るなら [学びの入口](../learning.md) へ

> **このメモは、そのまま就活で見せられる材料になります**（[計画書 §15](../plan.md)）。
> 「何を作ったか」より、**「どこで詰まって、どう抜けたか」のほうが読まれます。**
