notes/ — 詰まったことと、分かったことの置き場#

ここは「調べた結果」と「詰まった記録」を置く場所です。

Discuss.md の 8/17 で、こう依頼が出ています:

ログファイルを清書するときは詰まった点や工夫した点など振り返りを書くように事細かく冗長に書こうと思っています。 思い返せるように、個人が作成した範囲でメモを残しておいてください

その置き場がここです。 進捗ログ は週1回の要約なので、詰まった中身までは入りません。細かい話はこちらに1本ずつ書いて、進捗ログからはリンクするだけにします。

何を書くか#

書くもの例
詰まって、解決したこと「import が通らなかった。原因は◯◯だった」
調べて分かったこと「Blender の CLI レンダリングはこう書く」
比べて選んだこと「マスクの方式を4つ比べた」（→ T07）
相手のジャンルへの説明自分が作った部分を、専門外の相手に向けて説明する1枚（計画書 §3-7）

書かなくていいもの：週次の実働時間（→ 進捗ログ）、決定の理由（→ 決定記録）、仕様（→ 計画書）。

ファイル名#

<日付>-<内容>.md か <内容>.md。どちらでもよいですが、後から探せる名前にしてください。

docs/notes/blender-entry.md              # 恒久的に引くもの
docs/notes/mask-options.md               # 比較・検討したもの
docs/notes/2026-08-20-icloud-venv.md     # 一度きりの障害記録

書くときのコツ#

  • 冗長でかまいません。 Discuss.md の依頼どおりです。削るのは後からできます
  • 「当たり前すぎて書くまでもない」と思ったことこそ書いてください。 3か月後の自分には当たり前ではありません
  • 解決していなくても書いてよいです。「ここで止まっている」は立派な記録で、相手が拾えます
  • 用語で迷ったら 用語集、資料が要るなら 学びの入口 へ

このメモは、そのまま就活で見せられる材料になります（計画書 §15）。 「何を作ったか」より、「どこで詰まって、どう抜けたか」のほうが読まれます。
