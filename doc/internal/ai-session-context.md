## 新しいセッションの開始時の前提

**以下は決定済み。再検討・再提案は不要。**

- **開発テーマは確定済み。**（handoff §2）**2026-08-16 に松田の了承と志望分野の判明により、テーマ再検討の分岐は完全に閉じた**（D-30）。第二候補「物理シミュレーション × Unity」は破棄済み
- **使用言語は Python 単一で確定。**（handoff §8、計画書 §7）**2026-08-16 に松田から「遅ければ C++ でも」との提案があったが不採用**（D-32）。速度は Numba・行列化・チャンク分割で対処し、E7 の題材にする
- **Python のバージョンは 3.11 で確定済み。** 仮決めではない（2026-08-15、松田の実機確認。計画書 §7-2 / D-15）。**Blender内蔵 numpy は 1.26.4 で確認済み**（D-17）
- **ボクセル解像度は 256³ 維持**（松田のPCは 16GB。D-32）。**チャンク分割は解像度に依らず採用**（D-21）
- **計画書 §0 の決定事項は全て確定済み。** 覆す提案をする場合は、**決定記録の該当項目に書かれた根拠に反論すること。**
- **リポジトリは `4bitcom_HandM` を使用**（D-27）。**3D復元専用にしてよいと松田が回答済み（2026-08-16）**

### 分担の扱い（2026-08-16 改訂・重要）

- **担当は「人」ではなく「作業ジャンル G1〜G9」で管理する**（D-36、計画書 §3-3）。**人ごとの担当表は廃止済み。復活させる提案をしないこと**
- **誰がやるかは着手時に決める。** 計画書に個人名で担当を書き込まないこと
- **個人の研究志望に紐づく記述は計画書から削除済み**（D-37）。**技術核3つ・研究助走・志望研究室・研究室訪問向けの語り口は復活させない。** 技術的な中身（バンドル調整・離散ラプラシアン・E6 など）は**そのまま維持**
- **メンバー追加を検討中。** 文書は「新しく入る人が読む」前提で書くこと

### 参加者について、AIが踏まえるべき前提（2026-08-16 時点）

- **Python 歴が数か月のメンバーがいる**（主言語は C）。numpy / OpenCV / bpy / pytest はいずれも未経験。**Git は clone / commit / push まで**
- **「生成AIを用いたコーディングを控えたい」という申告がある**（D-33）。**この方針を尊重する。「AIに書かせれば速い」という提案をしないこと**
- **担当を減らす方向の提案もしないこと。** 入口の段差を均す形で対応済み（計画書 §7-7）

## 検討したが却下された提案（再提案不要）

**却下理由つきの一覧は [決定記録 D-26](../3d-reconstruction-decisions.md#d-26) にある。** 見出しのみ再掲。

- スコープ削減3件（Marching Cubes / UV展開を自作しない、前処理を2種に限定。計 −45h）
- 実写データのみで進める／実写と合成を最初から並行
- 完全な役割分担（松田＝作業の受け皿）
- **副担当はレビューのみ・実装しない**（2026-08-15 改訂 → D-04。**さらに 2026-08-16 に「主担当／副担当」の枠組みごと撤回 → D-36**）
- リポジトリを2つに分ける
- 大学のPBL・演習科目向けの提出文書を整備する
- 関口の開発環境を Ubuntu 単独に絞る
- Unity / C++ / Rust の採用
- 「①を完成させてから④」の順次開発

**2026-08-16 の松田の回答のうち採用しなかったもの**は [決定記録 D-34](../3d-reconstruction-decisions.md#d-34) に一覧がある（C++ 導入／レンダラ自作・品質作り込み／被写体としての風景・ぬいぐるみ）。

**再提案する場合は、D-26・D-34 に書かれた却下理由に反論すること。**

## 文書運用のルール

このプロジェクトの文書は役割で分かれている。**書き足すときは置き場所を間違えないこと。**

| 内容 | 置き場所 |
|---|---|
| 決まったこと（仕様・手順・日程） | 計画書 |
| **なぜそう決めたか**（根拠・代替案・却下理由） | **決定記録**。計画書には書かない（肥大するため） |
| 週ごとの実績 | progress-log |
| 松田への質問 | 確認シート第2版 |
| 人間が最初に見るもの | README |

**決定を変えたときは、決定記録の項目を消さずに改訂履歴として追記する**（「かつてこう決めていて、こういう理由で変えた」が残っていること自体が共同開発の説明材料になるため）。
