## 検討したが却下された提案（再提案不要）

**却下理由つきの一覧は [決定記録 D-26](../3d-reconstruction-decisions.md#d-26) にある。** 見出しのみ再掲。

- スコープ削減3件（Marching Cubes / UV展開を自作しない、前処理を2種に限定。計 −45h）
- 実写データのみで進める／実写と合成を最初から並行
- 完全な役割分担（松田＝作業の受け皿）
- **副担当はレビューのみ・実装しない**（2026-08-15 改訂 → D-04）
- リポジトリを2つに分ける
- 大学のPBL・演習科目向けの提出文書を整備する
- 関口の開発環境を Ubuntu 単独に絞る
- Unity / C++ / Rust の採用
- 「①を完成させてから④」の順次開発

**再提案する場合は、D-26 に書かれた却下理由に反論すること。**

## 文書運用のルール

このプロジェクトの文書は役割で分かれている。**書き足すときは置き場所を間違えないこと。**

| 内容 | 置き場所 |
|---|---|
| 決まったこと（仕様・手順・日程） | 計画書 |
| **なぜそう決めたか**（根拠・代替案・却下理由） | **決定記録**。計画書には書かない（肥大するため） |
| 週ごとの実績 | progress-log |
| 松田への質問 | 確認シート第2版 |
| 人間が最初に見るもの | README |

**決定を変えたときは、決定記録の項目を消さずに改訂履歴として追記する**（「かつてこう決めていて、こういう理由で変えた」が残っていること自体が共同開発の説明材料になるため）。

## 注意：文書が長くなりすぎた経緯

2026-08-15 時点で doc 配下が4000行を超え、**関口から「どれを読めばいいか分からない」という指摘があった。** そのため：

1. `README.md` を人間向けの唯一の入口として新設
2. 手続き用・履歴用の文書を `internal/` に分離（本ファイルを含む）
3. 計画書から「セッション引き継ぎ用」の記述を本ファイルへ移動

**今後、文書を追加・拡張するときは「人間が読む必要があるか」を先に判断し、無ければ `internal/` に置くこと。** README は短く保つ。
